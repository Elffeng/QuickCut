# 团队接口与交付契约 0.1.0

**日期：2026-11-06。状态：下一阶段设计提案。** 本页定义六位同事并行开发时共同使用的数据语言；它尚未成为现有 QuickCut CLI/API 的实现。任何字段冻结和变更应由字段生产方、消费方共同确认。

现有单视频 `Timeline` 仍可用于 MVP 演示。多素材、外部空镜、多轨工程和跨模块修改的正确性，需要显式的素材身份、两套时间坐标和版本引用。这里不把剪映私有格式当作内部数据模型；F 单独适配目标剪映版本。

## 1. 我们用这些数据共同完成什么

用户提供的是一组视频和一段成片要求。A 将素材变成统一资产与候选片段；B 根据 C 提出的需求召回用户素材与外部空镜；C 将实际可用素材对齐成故事板，并确定旁白文本；D 将故事板编译成多轨时间线；E 返回逐句音频和真实时长；D 决定最终声音与画面如何排列；F 按同一时间线生成预览和目标剪辑软件工程。

因此，这些契约不是八个新的微服务。首版可以在同一个 Python 项目中，以函数调用和版本化 JSON 文件交接；接口稳定之后再决定是否使用独立进程或任务队列。

| 对象 | 唯一生产责任方 | 消费方 | 代表什么 |
|---|---|---|---|
| `Brief` | C，来源为用户输入 | A/B/C/D/E/F 按需读取 | 主题、故事目标、风格、语言、时长与成片约束 |
| `AssetManifest` | A；外部库元数据由 B 提供后按同一规范注册 | B/C/D/F | 真实素材与候选片段的身份、来源、时间、媒体参数 |
| `RetrievalRequest` | C | B | 每个故事段落需要怎样的主镜头或空镜 |
| `CandidateSet` | B | C | 检索返回的候选与证据；不决定最终故事 |
| `StoryPlan` | C | D/E | 叙事目的、镜头选择与建议顺序、空镜职责、旁白文本、时间预算 |
| `VoicePackage` | E | D/F | 逐句音频、实测时长、局部字幕与适配结果 |
| `EditTimeline` | D | E 按需读取、F | 最终轨道、剪辑点、成片时序和渲染意图 |
| `ExportManifest` | F | D、用户、验收人员 | 导出物与软件版本、素材打包信息、实际导入验证状态 |

外部空镜的目录维护、标签和检索属于 B；其媒体信息必须遵守 A 的资产格式。可以由 B 调用 A 的索引入口生成外部库索引，避免两套重复的元数据和时间规范。第一轮不强制把整座外部库复制进每个项目：只有入选素材进入交付包，并保留库条目的身份及来源信息。

## 2. 所有模块共享的基本约定

### 2.1 公共信封与精确版本引用

每份文档都有以下字段：

| 字段 | 类型与规则 | 用途 |
|---|---|---|
| `schema_version` | 字符串，当前提案为 `0.1.0` | 表达字段结构版本，与项目内容 revision 分开 |
| `kind` | 八种文档名之一 | 让校验器和消费者知道对象类型 |
| `document_id` | 非空、稳定的字符串 | 文档身份，不随一次重新计算改变 |
| `project_id` | 同一项目全链路一致 | 防止串用其他项目的候选或音频 |
| `revision` | 正整数；内容变化即递增 | 对同一文档进行精确版本引用 |
| `fixtures_only` | 布尔值 | 夹具为 `true`；生产导出必须拒绝夹具数据 |
| `owner` | A/B/C/D/E/F | 明确写入责任 |
| `inputs` | `{kind, document_id, revision}` 数组 | 记录本次计算消费了哪一版上游结果 |

示例：

```json
{
  "schema_version": "0.1.0",
  "kind": "StoryPlan",
  "document_id": "story-001",
  "project_id": "project-forest-vlog-001",
  "revision": 1,
  "fixtures_only": true,
  "owner": "C",
  "inputs": [
    {"kind": "Brief", "document_id": "brief-001", "revision": 1},
    {"kind": "CandidateSet", "document_id": "candidates-001", "revision": 1},
    {"kind": "AssetManifest", "document_id": "manifest-001", "revision": 1}
  ]
}
```

模块不得只写“使用最新素材”。交接时必须携带精确 revision。上游内容已改变而旧结果尚未重算时，D 标记下游 `stale` 并阻止最终导出；不能因为文件名相同就继续复用。首版按整份聚合文档判定旧 revision 失效，但生成新 revision 时可以复用未变更的句子音频：E 根据 cue 文本、音色、引擎和适配参数确认复用条件，D 重新计算受影响的成片位置。整份旧 VoicePackage 被拒绝，不等于每句 WAV 都必须重新合成。更细的跨模块依赖图可后续扩展。

### 2.2 身份与层级

- `asset_id`：一个真实视频、音频或图片文件的身份。用户视频、外部空镜、生成配音共享这一概念；不能拿镜头 ID 代替文件 ID。
- `segment_id`：一个素材里的区间，必须同时引用 `asset_id` 和 `asset_revision`。粗事件可以通过 `parent_segment_id` 关联更细镜头。
- `beat_id`：故事段落的身份。与文件边界无关，一个事件可以跨文件，一个文件也可以包含多段事件。
- `cue_id`：一条被批准的配音句子的身份；脚本、WAV、字幕和时间线必须能通过它关联。
- `track_id`：成片中的画面、原声、旁白、字幕等轨道身份；`clip_id` 是轨道上的具体实例。同一素材在不同位置使用时创建不同 clip，不能复用同一 clip ID。

素材 ID 建议使用 UUID 或稳定命名的随机 ID；内容哈希用于去重和失效检测。素材路径不是身份，移动项目目录不应使故事引用失效。样例中的可读 ID 只是便于团队理解。

### 2.3 时间、帧率与变速

**所有时间用整数微秒，所有区间为半开区间 `[begin, end)`。** 不使用含义不明的 `start: 3.0`。

| 字段 | 坐标系 |
|---|---|
| `source_range_us` | 相对于所引用源素材起点 |
| `source_time_us` | 某张关键帧在源素材中的位置 |
| `timeline_range_us` | 相对于成片起点 |
| `local_subtitles[].range_us` | 相对于该句生成音频的起点 |
| `duration_budget_us` | 规划阶段的预算，不等同于已确定的成片区间 |

例如源视频 `40–46s` 的内容放在成片 `9–15s`：

```json
{
  "asset_id": "asset-long-01",
  "source_range_us": {"begin": 40000000, "end": 46000000},
  "timeline_range_us": {"begin": 9000000, "end": 15000000},
  "playback_rate": {"numerator": 1, "denominator": 1}
}
```

帧率单独使用分子/分母，例如 `30000/1001`，不得截成整数 30。D 决定出入点的帧边界和误差容忍规则；F 转换为导出目标的 timebase，并记录发生的舍入。首版黄金样例使用固定 30 fps 和 1 倍速，满足：

```text
源区间长度 × playback_rate.denominator
= 成片区间长度 × playback_rate.numerator
```

素材是 VFR 时，由 A 保留原始时间信息和代理映射，D/F 根据 PTS 而不是“帧号除以平均帧率”反算原片位置。变速画面对应的原声处理方式需要写进轨道策略，不能让画面变速而原声按另一套时间播放。

### 2.4 文件引用与来源

- `uri` 在这版契约中表示**项目根目录下的相对文件路径**，使用 `/` 分隔；不得写某位同事机器的绝对路径。
- 引用包含 `asset_id`、`asset_revision`，真实媒体带内容哈希。预览代理和原片分别记录；导出不能不经声明地拿低清代理代替原片。
- `origin` 为 `user / external / generated`。外部库条目保留库 ID、来源记录及可用范围，用户素材和外部空镜不能被混为“同一地点真实发生”的事件证据。
- E 的生成音频清单保存在 `VoicePackage.assets`，F/D 使用 A 与 E 两份清单的并集解析资产；ID 不得冲突。后续可以统一注册到项目资产仓库。
- F 打包时复制或明确引用实际使用的素材，生成重定位映射。是否复制整个源文件、是否使用可重定位链接由目标工程能力决定，必须写入导出报告。

## 3. 八个对象的最小字段

### 3.1 `Brief`：用户需求是整个流程的起点

`requirements` 至少包含 `story`、`format`（VLOG/微电影等）、`language`、`target_duration_us`、`aspect_ratio`、`tone`、`narration`、`broll_policy`、`target_editor`。`constraints` 记录本地推理、原声保留、可编辑轨道等要求。

用户的“希望讲述的故事”和素材已经发生的事实要分开。C 可以根据可用证据缩减、调整表达，并把无法成立的事件写入缺口；不能在生成脚本时把目标故事当成已拍到的事实。

### 3.2 `AssetManifest`：素材事实由 A 统一维护

| 字段 | 要求 |
|---|---|
| `assets[]` | 文件 ID/revision、类型、来源、URI、哈希、时长、视频宽高/fps、音频参数、代理路径 |
| `segments[]` | 区间 ID、asset 引用、源时间、颗粒度、父区间、关键帧与 transcript |
| `quality` | 当前检查结果和明确 flag；缺失信息不能写成“通过” |
| `embedding_profile` | 模型 ID、后端、向量维度及索引版本；实际向量可外置保存 |

切分由粗到细：文件 → 事件/场景候选 → 镜头候选。A 提供稳定的初步切分；D 只在选定内容附近进一步细化出入点。若 D 需要超出已批准的候选区间，应先生成新的区间引用并更新选择记录，不能让剪辑点悄悄扩展到未知素材。

### 3.3 `RetrievalRequest`：C 向 B 提出的需求

`queries[]` 每条包含 `query_id`、`beat_id`、`semantic_text`、镜头 `role`、`allowed_origins`、时间预算与 `top_k`。可扩展画幅、运动方向、光线、地点类别等过滤条件。`iteration / max_iterations` 显式约束检索循环。

建议的职责名包括 `primary`（人物/动作）、`establishing`（建立环境）、`transition`（转场）、`atmosphere`（情绪留白）、`detail`（细节）。职责比“随便找一段风景”更能帮助 B 返回有效空镜。

### 3.4 `CandidateSet`：召回结果不等于最终决定

`results[]` 必须逐条对应请求里的 `query_id`，即使没有结果，也要返回 `status: empty` 与原因。候选包含 `candidate_id`、`segment_id`、素材 revision、视觉/文字/质量分、综合排序分、来源和证据。

分数必须携带 `score_profile` 或模型/融合版本；颜色直方图、CLIP cosine 和关键词匹配不是同一统计分布。不得跨模型直接比较一个未校准的“0.8”。B 负责排序并提供候选，C 决定采用哪一个以及安排在哪里。

### 3.5 `StoryPlan`：可执行故事板

每个 `beat` 记录 `beat_id`、顺序、叙事目的、时间预算、选定镜头及职责、旁白句子 ID。每个 `shot` 同时引用候选 ID 和片段 ID，便于追溯召回与最终选用的关系。

`narration_cues[]` 包含 `cue_id`、`beat_id`、批准文本、时间预算、声音风格、证据片段 ID。`unresolved_gaps[]` 列出缺失人物/动作/结尾等问题，并明确解决建议。`decision_provenance` 记录使用的模型调用、规则调整和人工审阅，而不是把所有结果都标成“Qwen 自动选择”。

段落时间预算之和应符合 Brief 约束，但它不是最终时序。E 不以预算假装已经获得真实语音；D 可以在语音实测后重新分配段落长度。

### 3.6 `VoicePackage`：返回声音事实与时长问题

| 字段 | 要求 |
|---|---|
| `assets[]` | 逐句音频文件、音频格式、真实时长、内容哈希 |
| `cues[]` | 对应句子 ID、原文、所属段落、音频 ID、原始/处理后时长、局部字幕 |
| `fit_status` | `fits / needs_retime / failed` |
| `tempo_ratio` | 实际采用的变速比例；没有变速则为 1 |
| `needs_retime` | 声音无法在可接受语速下满足预算时为 true |
| `synthesis_profile` | 引擎、模型/音色版本、语言、语速/风格、本地运行标识 |

**E 不修改画面顺序，不编造语音时长，不自行截掉句尾。** 若声音太长，返回实际 WAV 和 `needs_retime`；D 尝试调整镜头或空镜长度，若仍无法满足则交 C 缩短文案。字幕文本来自批准脚本，ASR 用于核验，不用识别错字覆盖脚本。

没有明确画面句子区间时，E 先返回句子自身的局部时序。D 把它映射到成片。若 D 已给出明确句子区间，E 应在本次生成请求中记录该区间和基于的时间线 revision，并在回复里回显；D 只接受与当前请求匹配的回复。这类重合成请求可作为任务元数据保存，不要求首版增加一个新的核心文档种类。

### 3.7 `EditTimeline`：D 是全局时序的唯一所有者

| 轨道类型 | clip/cue 至少包含 |
|---|---|
| `video` | clip ID、asset/segment 引用、beat ID、职责、源区间、成片区间、变速、原声策略 |
| `source_audio` | 源素材与源区间、成片区间、关联的画面 clip、增益 |
| `narration` | cue ID、生成音频 asset 引用、源区间、成片区间、增益 |
| `subtitle` | 字幕 ID、cue ID、文本、成片区间、可编辑标识 |
| `music / sound_effect` | 音频素材、源/成片区间、增益与可选音量包络；首个夹具暂不包含 |

`output` 记录画幅、分辨率、fps、采样率；`render_policy` 区分“预览可以烧录字幕”和“工程导出必须保留文字轨”。静态增益、淡入淡出、ducking 等参数应作为显式意图，F 负责一致执行。

基础版本要求单轨无意外重叠，画面完整覆盖成片区间。跨轨并行是正常情况，例如画面与旁白；以后加入叠化时，需要明确 overlap/effect 语义及导出能力映射，不能让通用无重叠检查把合法叠化当作错误。

### 3.8 `ExportManifest`：不能把写出文件等同于导入成功

至少保存：输入时间线 revision、目标软件名称/实际版本/平台、适配器版本、工程根目录、文件清单、素材重定位映射、预览与编辑工程路径、警告与导入验证记录。

建议状态：`not_exported → generated → verified_import`，失败用 `failed` 并附明确原因。只有在指定剪映版本真实打开、编辑、保存，并检查素材路径后，才允许记录 `verified_import`。未支持的效果或轨道需显式报错或经用户选择降级；不能在导出时悄悄烧成一整段视频并声称“各轨可编辑”。

本仓库当前没有可用的剪映导出适配器，黄金样例中的目标版本为 `UNVERIFIED`。F 的第一项任务就是以两段画面、独立旁白和可编辑字幕做真实导入实验。

## 4. 黄金样例如何贯通六人交接

本例时长 18 秒，只用于让接口清楚可测，不是最终剪辑风格标准。

| 成片区间 | 画面来源 | 源区间 | 责任与声音 |
|---|---|---|---|
| 0–6s | 短视频 1：出发准备 | 3–9s | 主镜头；保留独立原声；cue-01 在 0.2–5.4s |
| 6–9s | 外部空镜 1：林间光线 | 2–5s | 环境过渡；不声明为用户实际地点；该占位文件无音频 |
| 9–15s | 长视频：人物步行 | 40–46s | 主镜头；保留独立原声；cue-02 在 6.2–14.4s，跨空镜与动作镜头 |
| 15–18s | 短视频 3：坐下休息 | 1–4s | 结尾；保留独立原声；cue-03 在 15.2–17.4s |

短视频 2 和外部空镜 2 是候选但未入选，说明“进入素材库”不意味着“必须出现在成片”。三个音频文件和字幕分别放在各自轨道，后续可以换一句声音、移动一条字幕或替换空镜。

执行：

```bash
python examples/team_contracts/validate.py --self-test
```

校验器使用 Python 标准库检查八份文档的引用与时序，并用五个负例确认能拒绝：陈旧 revision、目录越界、源区间越界、字幕文案不一致、虚假的导入成功声明。媒体文件不存在是夹具的明确属性；该校验器不检查真实模型推理或真实剪映格式。

## 5. 修改之后哪些东西失效

| 变更 | 应保留/复用 | 必须重算或复核 | 发起方 → 负责方 |
|---|---|---|---|
| 新增素材 | 旧素材索引与哈希 | 新素材索引、受影响候选与故事覆盖 | A → B/C |
| 原文件内容变化 | 不受影响资产 | 该资产索引、依赖它的候选/故事/时间线 | A → B/C/D |
| 故事目标或语言变化 | 原始素材索引 | 检索请求、故事、脚本、配音和时间线 | C → B/D/E |
| 替换镜头 | 无关镜头和 WAV | 该段事件证据、旁白匹配、画面与原声区间 | D → C，必要时 E |
| 重排镜头 | 原始媒体、未改文本的配音文件 | 故事因果、字幕/声音位置、混音和导出 | D → C/E/F |
| 改一句旁白文本 | 其他句子的 WAV | 对应 cue 合成、字幕、该区间时序 | C → E/D |
| 只换音色 | 素材选择与文字 | 音频实测、时间线适配、预览和工程包 | E → D/F |
| 调整画幅或导出软件版本 | 素材身份、故事文本 | 裁切策略、字幕布局、目标效果映射、实际导入验证 | D/F |

更新采用新 revision，不覆盖旧产物后声称缓存仍有效。建议运行目录按 `project_id / stage / revision` 保存，并记录输入哈希、模型参数、运行日志与错误；旧结果可以用于追溯，不能在当前工程里偷偷替代失败的新结果。

## 6. 有限反馈循环和失败结果

这部分是团队约定的建议默认值，不是当前运行时已有的自动重试机制。

### B ↔ C：故事与素材二次对齐

1. C 发出分段检索请求，B 按原请求返回候选或明确空结果。
2. C 判断是否足以表达段落；不足时可以放宽非关键风格条件、调整叙述方式或安排有明确职责的空镜。
3. 默认同一缺口最多检索 3 轮；仍没有事件证据时，保留缺口并要求编辑决策，不能无限检索或编造人物行为。

### D ↔ E：声音与画面对齐

1. E 逐句合成并返回真实时长。适配比例应在项目允许范围内；大幅变速必须被显式标记。
2. D 优先利用合理停顿、镜头延长或可用空镜调整区间。若需要改变事实和文案，交给 C。
3. 默认同一句最多自动适配 2 轮；仍超预算返回 `needs_retime`，停止该版最终导出并提供待处理 cue 列表。

### 模块统一错误信封（建议）

```json
{
  "status": "failed",
  "code": "STALE_INPUT_REVISION",
  "stage": "timeline",
  "project_id": "project-forest-vlog-001",
  "message": "StoryPlan 已更新，本次配音基于旧版脚本。",
  "retryable": false,
  "affected_ids": ["cue-02"],
  "action_owner": "E"
}
```

| 错误码 | 含义 | 下一步负责人 |
|---|---|---|
| `MEDIA_UNREADABLE` / `KEYFRAME_MISSING` | 索引输入损坏或关键帧无法读取 | A |
| `NO_CANDIDATE` | 合法检索但没有候选，通常属于空结果而非服务崩溃 | B 返回原因，C 决定调整 |
| `UNSUPPORTED_STORY_BEAT` | 缺少支撑具体人物/事件的证据 | C |
| `VLM_INVALID_PLAN` | 非法 ID、漏掉必需动作、超预算或错误结构 | C |
| `STALE_INPUT_REVISION` | 接口引用已过期或项目不一致 | 当前消费方拒绝，上游重算 |
| `TIMELINE_INVALID` | 越界、非法重叠、音画源区间不一致 | D |
| `VOICE_NEEDS_RETIME` / `TTS_FAILED` | 语音超时或生成失败 | E 返回事实，D/C 处理时序/文案 |
| `EDITOR_VERSION_UNSUPPORTED` / `EDITOR_IMPORT_FAILED` | 目标工程能力或实际导入失败 | F |
| `PACKAGE_MISSING_MEDIA` | 工程引用缺失或素材移动后不可解析 | F，必要时 A/E |

不要把“返回了一个 MP4”当作所有错误已解决。流程状态必须区分可预览、仍需编辑和已通过最终交付验收。

## 7. 从当前 MVP 渐进迁移

当前模型见 [quickcut/types.py](../../quickcut/types.py)：`Timeline.source_video` 是单一路径，`TimelineItem.asset_id` 实际上经常装的是 `shot_id`，`start/end` 使用浮点秒。多素材版本必须改变这些语义，不能只把 `source_video` 改成列表。

建议迁移顺序：

1. **建立兼容转换器和新契约样例。** 现有单视频 Manifest 注册为一个真正的 asset；旧 `shot_id` 转为新 `segment_id`；旧 item 的 `asset_id` 先通过 shot 查到源素材，再转换，不能直接当作新文件 ID。
2. **先将 D/F 的输入切换成显式多轨时间线。** 旧时间线的成片位置由各 item 的时长累加得到；原声拆成显式链接画面的音频轨；旧旁白和字幕转换成 cue 引用。
3. **接入 A/B 的多源索引和两类素材库。** 主素材与外部空镜都遵守统一资产结构，但保留来源角色，不把两类库的检索结果混为事实证据。
4. **接入 C 的两次故事对齐与 E 的逐句实测。** 淘汰“编辑 items 后保留旧字幕/旧文案不变”的行为；由 D 管理依赖失效与局部重算。
5. **F 实现具体剪映版本的导出适配。** 当前 FFmpeg 渲染能力可复用，工程文件生成与真实导入验证另建测试；内部契约不随目标软件私有字段变化。

迁移期间，两种版本分别标明，不让同名字段承担两种含义。M0 先通过黄金样例校验，M1 每个模块能独立消费/产生约定对象，M2 使用真实上游产物贯通，M3 再验收编辑后重算与剪映精修。

## 8. 协议修改与交接清单

- 生产方提交字段变化、迁移示例和受影响消费者列表；消费方确认后再合并。
- 字段新增尽量可选；改变 ID、时间单位或引用语义必须升级 schema 并提供转换路径。
- 每次交付提供一个无需模型的固定样例，以及一份真实运行结果。两者的 `fixtures_only` 与证据说明必须清楚。
- 交接时检查输入 revision、错误状态、媒体路径、时间单位、来源、文本与音频匹配，最后才检查视觉效果。
- 自动校验只证明数据满足约束；语义正确性、声音自然度与剪映实际可编辑性必须由相应模块的真实验证补充。
